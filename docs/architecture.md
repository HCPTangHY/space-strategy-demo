# 政治经济架构设计规范：机制与数据边界总纲

本文档确立 `game-core` 政治经济系统的完整架构设计与“机制—数据”分界标准。系统覆盖单星球多辖区至多星球星际网络尺度，兼容现代中央地方分税体制、跨国直接投资与特许托拉斯经营，以及全封闭守恒的货币与多商品市场循环。

---

## 一、核心设计原则

### 1. 纵向分层：主体决策层 vs 客观结算层
系统在纵向上严格拆分为两层，禁止在客观结算函数中替自主实体硬编码经营、人事或外交选择：

- **主体交互决策层（`decision.rs`、`rules.rs` 事件脉冲与玩家指令接口）**
  - 凡涉及两个自主实体之间的交互，或主体对自有资产与富余资金做出的处置（招工裁员、盘口报价、余钱分配消费与证券投资、拿地建厂、双边契约签署、到期债务与契约的履约或违约抉择、有偿赎买与强制国有化），均归属本层。
  - 玩家手动控制的主体与 AI 自动运行的主体共用同一套状态控制接口、权限校验和事件选项，不存在玩家专属免责通道。
- **客观物理与清算层（`settlement.rs` 与 `market.rs`）**
  - 仅执行单个容器内部的物理转化与生理消耗、流量商品月末清零、无条件超额利润归集、法定税率源头拆分直征、提交挂单后的中立集合竞价出清，以及连续资不抵债时的破产清算退出。
  - **严格守恒原则**：除中央银行按货币政策铸币外，零凭空印钱、零凭空造物、零反向倒贴补亏。每一分货币（`base:cash`）与每一单位实物或金融证券均须在真实 `Inventory` 容器之间原子划转。

### 2. 横向分层：代码机制 / 静态配置数据 / 声明式规则与事件数据
系统在横向上划分为三类职责：

1. **代码机制（Rust 引擎原语）**：提供与具体内容名称完全无关的容器、矩阵算子、盘口撮合器、多级政权树与投资准入校验、单槽配方执行器、三容器周转储备与余钱流转框架，以及通用的条件树求值与效果执行器。
2. **静态配置数据（Catalog 数据表）**：定义商品与证券属性、市场撮合制度参数、建筑槽位规则与投入产出配方、职业属性与清偿顺位、空间网络连边与枢纽参数、政权上下级分税比例与投资准入关系。
3. **声明式规则与事件数据（`if-else +-` 规则表与事件定义）**：以纯数据条件分支、权重增减与原子效果列表，描述 AI 主体的消费投资倾向、双边契约与债券票息履约抉择、民间商业设施与企业组建脉冲，以及跨国资产没收或地方债违约等政治经济互动。

## 二、主体架构：多级同构政权树、无地企业与跨区投资权

系统不单独设立“地方政府类”或“独立国企类”结构体，而是通过以下五类主体原语覆盖现代国家治理与跨国商业扩张：

### 1. 多级同构政权树（`Polity`：中央 — 星区 — 星球 — 大区）
- **同构公法人结构**：中央政府、星区总督（可选）、星球政府、大区政府在代码机制上均为同一种 `Polity` 实体，各自拥有独立的财政金库 `Polity.vault` 与独立的信用评级 `credit_rating`，通过可选的 `parent_polity: Option<PolityId>` 组成树状层级。
- **`Sector` 与地理大区 `SurfaceRegion` 分离及直辖行政力框地**：
  - 地理大区 `SurfaceRegion` 为自然气候与运力分片（地球 13 陆区 / 殖民星 12 陆区，生成时自动在远离陆地省界缝隙处标定 `1~2` 个腹地中心或天然良港候选格 `TileTag::CoreSite`，限制首府、大区核心与殖民据点选址）；
  - 政权辖界不受地理大区边界限制：每个政权拥有非盘口直辖行政额度 `base:admin`（`GoodDef.non_market = true`，由在岗首府、大区核心、殖民据点按比例供给），每实控 `1` 格陆地消耗 `1` 份行政力；
  - 连片框入无主荒野陆格（`sector_id = u16::MAX`）时，引擎按 `(geo_region_id, owner_polity)` 自动并入既有辖区或生成分离省 `Sector(G, P)`（共享同一地理大区的不同政权分离省之间天然免运费、仅收关税）；在空白新大区 `CoreSite` 建立零外部水电输入的 `殖民据点` 时，按人数比例守恒迁入同政权先遣人口与家庭资产激活新市场。
- **现代“一级政府、一级财政、一级产权”与源头分税直征**：
  - **产权边界**：各级政府对自身出资兴建的国有槽位（`BuildingOwner::State { polity_id }`）与自身 `Polity.vault` 享有独立公法人产权。上级政府不得直接挪用下级金库现金，亦不得越过协议直接改拆下级政府出资的地方公企。
  - **中央权威来源**：货币发行权归属主权顶层政权；基层税源（工场利润税、居民人头税等）在结算扣款源头即按法定分税比例拆分为上级国税与本级地税——国税大头直接划入上级/中央国库，不经地方金库中转；地方金库仅收取法定地税留成、本级地方公企税后纯利及上级拨付的转移支付。
- **合法跨级交互**：在主权树范围内（目标辖区沿 `parent_polity` 向上可追溯至当前政权），上级政权可直接动用本级国库在下级辖区空槽投资兴建本级直属公企（央企），可通过通道三越过中间层级直接向基层大区拨付专项资金、签署采购契约或认购地方政府债，亦可调整行政树将重点大区改为直辖。

### 2. 跨国直接投资权与特许托拉斯（满铁模式）
- **属地与产权彻底分离**：地块的行政属地（`tile.sector_id`，决定用工来源、商品进出盘口及东道国属地税归属）与槽位出资人产权（`BuildingOwner`，决定控制权与税后纯利归属）完全分离。
- **统一投资准入校验**：任何政权或外资主体在某辖区新建建筑，统一校验“是否拥有对该辖区的投资准入权”。本国主权树下辖区天然放行；外国辖区（可为全境开放，亦可为条约指定的单一特定大区）通过通道三签署《外资准入协定》解锁。
- **国内跨级直投与跨国直投合一**：结算层按槽位 `State { polity_id }` 将税后纯利直接汇入对应 `Polity.vault`。因此“中央去地方省区建直属央企”、“甲省在乙省持有飞地农场”与“外国政府凭条约在别国大区直接出资建矿山”共用同一套结算代码。
- **国有控股与特许托拉斯（`Trust`）**：日常独资公营厂直接使用 `State { polity_id }`（单槽 `Workshop` 本身即独立核算盈亏）。若需组建跨国自主扩张的大型国企或政商合资特许公司，由政权以现金或已建成的境内外槽位资产作价，通过 `charter_trust` 组建 `Trust`（政府国库持有控股或半数股权商品，民间认购其余股份）：公司 AI 凭自有法人金库在开放投资权的境内外辖区自主扩建，利润按全盘 `Inventory` 实际持股比例向政府国库与股东人群派发分红。
- **东道国主权反制**：辖区所属主权政权对境内非本国产权槽位保有两项操作——按估值支付现金的**有偿赎买国有化**，以及不支付对价强行收回产权的**强制没收国有化**（执行后自动触发涉外违约事件，扣减信用评级并生成外交冲突后果）。

### 3. 本地民间投资池（`SectorCapital`）、具名企业（`Enterprise`）与人群（`PopGroup`）
- **`SectorCapital`（本地散户民间池）**：纯自动运行的辖区中小私营资本聚合池，不可扮演，严禁进入通道三（不可签双边合同、不可发债、无信用评级）。仅接收归属本区 `LocalPrivate` 槽位的税后纯利与本地富余储蓄注入，纯粹按利润率投建私营工场，与负责公共职能和民生兜底的地方政府 `Polity` 职责严格错开。
- **`Enterprise` / `Trust`（具名公司与股份托拉斯）**：持有独立于任何辖区 `SectorCapital` 的法人金库 `vault`，可跨辖区拿地经营、进入通道三签署双边包销契约及发行标准公司证券。
- **`PopGroup`（人群家庭）**：按 `(辖区 SectorId, 职业 PopTypeId, 族群 culture_id, 雇主产权 BuildingOwner)` 聚合，持有独立家庭 `Inventory`。取消无建筑凭空产粮的“自给个体民”，一切实物与服务商品均须由建筑槽位生产。

## 三、统一资金流转与商业服务体系

### 1. 三类容器统一的“周转储备 + 超额流转”算式
为防止任何容器无限囤积现金抽干市场流动性，工场、金库与居民家庭统一遵循“留够 `N` 个月周转金，超额部分向外流转”的同一套结构：

1. **单槽工场（`Workshop`）**：每个生产或服务槽位均拥有独立 `Workshop` 核算单厂收支与周转储备。留足 `N` 个月（在岗工资 + 原料采购）周转储备后，超额现金先按属地税率缴税，税后净额归集至归属主体：
   - **`LocalPrivate`（本地私产）**：超额纯利注入本地 `SectorCapital` 民间投资池；出现亏损时投资池不反向贴补，由工场自行缩编裁员、折价变卖存货，连续 3 个月欠薪资不抵债则进入破产处置（触发声明式事件 `base:private_bankruptcy` 或 `acquire_bankrupt_slot` 指令：本级/上级政府可按拆解残值收购并结清欠薪收归公有，否则直接清拆腾空槽位）。
   - **具名实体（`State` 政权 / `Enterprise` 企业 / `Trust` 托拉斯）**：超额纯利上缴归属实体金库，亏损产生周转缺口时亦由归属实体金库拨补（计入实体工场净收支）；单槽工场自身不因短期亏损擅自裁员，裁员与编制调整统一由归属实体决定（政权默认维持编制不因亏损裁员，仅在国库自身耗尽或手动下调编制时缩编；企业与托拉斯在法人金库吃紧时由实体统一缩减亏损分厂）。
2. **投资金库（`SectorCapital` / `Enterprise` / `Trust`）**：留足必要的运营储备后，按回报率或投资事件投建新槽位；`SectorCapital` 超出本区动态资金池上限的部分，月末 100% 溢出作为分红发放给本区分红阶层。
3. **人群家庭（`PopGroup`）**：留足 `N` 个月基础生存开销作为家庭应急周转金后，超出的富余现金按职业与收入规则拆分为两部分流回市场：
   - **超额消费**：在本地盘口挂买单增购商业服务或改善型消费品；
   - **金融与民间投资**：在公开盘口挂买单认购公债、企业债或托拉斯股票；若盘口暂无可买证券，允许符合条件的人群按规则将部分富余资金注入本区 `SectorCapital` 形成民间建厂资本。

### 2. 商业区彻底并入商品供需（零建筑专用字段、移除座数硬锁）
- **取消旧式私产座数硬锁**：彻底移除“无商业街限建 2 座私产、每座商业街限托管 6 座私产”的计数锁，以及挂牌私有化免费附赠商业街的特判。出资建造遵循“谁掏钱产权归谁”（政府国库出资归 `State`，民间投资池出资归 `LocalPrivate`）。
- **保持 `BuildingDef` 纯粹结构**：不在建筑定义上追加“资金池上限加成”等机制专用字段。建筑定义仅包含通用槽位位置规则 `SlotRule`（仅主槽 / 仅次槽 / 主次通用）、同格主槽前置建筑标签要求 `required_primary_tags`、岗位工时需求 `jobs_by_role` 与投入产出商品配方 `monthly_inputs -> monthly_output`。
- **商业服务流量闭环**：
  - 商业街作为普通次槽 `Workshop` 运行：雇佣职员与资本家工时，产出本地限定（`TransportChannel::LocalOnly`）、零体积、月末清零（`retention_permille = 0`）的“商业服务”流量商品；
  - 对月末清零的流量商品，买方仅按当月实际需求 `1.0` 倍挂单，不按实物商品多买囤积；
  - **温饱与满意度分离核算**：口粮满足度（`food_met`）单独决定生存温饱与待业赤贫降级；商业服务满足基础生活档位后，居民用富余资金多买并消耗掉的超额服务量直接折算为当月额外的**娱乐与满意度加成**；
  - **动态放大民间投资池上限**：不在建筑上写死容量，而是在商品定义 `GoodDef` 上标注单位流量提供的资金池容量系数，按本辖区当月商业/金融服务的实际产出（或成交）量动态决定本区 `SectorCapital` 的池顶上限；
  - **事件驱动设施涌现**：当本辖区投资池资金水位或本地服务价格达到阈值时，通过触发声明式投资事件由 `SectorCapital` 出资兴建商业街；当本辖区同一行业标签下的私产积累达到阈值时，同样通过事件组建对应行业的具名企业园区（通用匹配任意行业标签，不绑死农业）。

## 四、尺度无关 `N × N` 矩阵与三条交互通道

### 1. 尺度无关 `N × N` 节点矩阵（`NodeMatrix`）
- 网络合成器 `NodeMatrix::from_spec` 接收节点数 `N`、直连边费率与运力、共享枢纽团 `HubCliqueRule`（沿海港口远洋互通或星际跃迁门互通）及可选的多跳中转开关，生成统一的费率与运力矩阵，并提供零和守恒的通用成对计算算子 `compute_pairwise_flows`。
- 空间市场出清器 `clear_spatial_good_market` 读取每种商品 `GoodDef` 上的 `MarketClearingRule`（长协池比例、成交定价模式、均价惯性权重），同一套撮合算式同时适用于单球内大区网络与星系内星球网络。

### 2. 三条实体交互通道权限边界

| 通道 | 发起主体 | 目标对象 | 允许的操作 | 权限与禁区约束 |
| :--- | :--- | :--- | :--- | :--- |
| **通道一：自有资产与准入拿地** | 各级 `Polity`、`Enterprise`、`Trust`、`SectorCapital` | 自身 `vault` 金库、拥有投资准入权的合规空槽、自有产权建筑槽 | 出资新建建筑、修改自有槽位目标编制、开关自有槽位薪资兑付、挂牌出售自有槽位、调整本级官仓政策 | 仅可修改产权归属自身的槽位（上级政府亦不可直接改拆下级政府槽位）；东道主权政权接管境内他人槽位须走有偿赎买或强制没收流程 |
| **通道二：公开盘口匿名竞价** | 全部 `PopGroup`、全部 `Workshop`、各级政权官仓、`Enterprise`、`Trust` | 各节点商品 `NodeOrderBook`、辖区各职业 `RoleWageBook` | 提交商品与服务买卖单、破产清算卖单、国债/地方债/公司债与托拉斯股权买卖单、招工与求职挂单 | 多对多匿名撮合，交易制度由 `GoodDef.market_rule` 数据控制；`LocalPrivate` 工场的购销与用工仅通过本通道完成 |
| **通道三：具名主体点对点契约与事件** | **仅限具名公私法人**：各级 `Polity`、`Enterprise`、`Trust` | 另一具名主体（各级 `Polity` / `Enterprise` / `Trust`） | 签署双边长期供货协议、签署跨国/跨区投资准入协定、上级对下级专项拨款、合资组建特许托拉斯、发行具名付息债权、到期事件选择履约或违约 | **`LocalPrivate` 与 `SectorCapital` 严禁进入本通道**：匿名散户池不可签署双边协议、不可发债、无信用评级 |

## 五、机制与数据完整划分总表

以下总表作为后续编码与填表工作的唯一分界依据：**左栏是写进 Rust 源码的通用机制，中栏与右栏是后续填充与调平的纯数据内容**。

| 领域 | 代码机制（Rust 引擎原语，不含具体名称与数值） | 静态配置数据（Catalog 结构化表） | 声明式规则与事件数据（`if-else +-` 与 `EventDef`） |
| :--- | :--- | :--- | :--- |
| **仓库与商品金融** | `Inventory` 容量与冻结守恒原语；`GoodCatalog` 动态注册；按全盘持仓自动派发股权分红与债权票息 | `GoodDef`：商品/服务/债券/股票 ID、体积、留存率（`0` 为当月流量）、运输通道、初始价、口粮需求系数、服务需求与超额转满意系数、战略官仓目标、月票息率、民间池容量系数 | 债券到期兑付或拒付事件（`EVENT_COUPON_CLAIM_DUE`）；地方债违约时上级政权是否救助事件 |
| **空间网络与盘口** | `NodeMatrix` 网络合成与零和成对算子；`clear_spatial_good_market` 两步集合竞价；`clear_local_labor_book` 劳动力撮合 | `NodeNetworkSpec`（大区陆海连边、远洋团、星际航道团费率与运力）；`GoodDef.market_rule`（长协占比、定价模式、均价平滑权重） | 贸易禁运、关税加征或航道封锁修正规则 |

| **人口与家庭收支** | 单一人口计数 `PopGroup`；24 个月滚动劳动合同、1 个月遣散费期中裁员、优先欠薪债权 `UnpaidWageClaim`；温饱降级与服务满意度双轨结算；家庭周转储备扣留与余钱拆分器 | `PopTypeDef`：职业 ID、基准薪资、清偿顺位 `redemption_tier`、分红资格、生活预期、晋升来源、赤贫降级目标 `demote_to`、家庭应急储备月数 | `Pop` 富余现金在“增购服务消费 / 盘口买证券 / 注入民间池”之间的 `if-else +-` 分配权重规则；求职底线折扣规则 |

## 六、代码模块树与外部 `gamedata/` 热重载目录规范

### 1. 纯机制代码模块结构（`crates/game-core/src/`）
- `actors/`：按经济层级与主体对象拆分为 `household.rs`（人群与家庭）、`workshop.rs`（单槽工场与欠薪债权）、`sector.rs`（大区辖区、民间池与空间交通拓扑）、`corporate.rs`（具名企业、特许托拉斯与双边契约）、`polity.rs`（政权与财政政策）。
- `market/`：拆分为 `inventory.rs`（商品定义与守恒仓库）、`order_book.rs`（盘口与节点网络矩阵）、`commodity_clearing.rs`（空间商品与捆绑运力撮合）、`labor_clearing.rs`（本地劳动力撮合）。
- `ai/`：独立 `config.rs`（`AiDecisionConfig` 决策启发式参数），与 `pricing.rs`、`hiring.rs`、`investment.rs` 三类 AI 自主经营行为分离，不混入客观物理容量或产出公式。
- `modifiers.rs`：未来 Buff 与属性修正系统的预留挂载入口（`StatModifier`）。
- `settlement/`：月度 12 阶段守恒清算、源头国地分税直征（`fiscal.rs`）与全盘货币实物守恒核查（`audit.rs`）。
- `scenario.rs`：独立硬编码开局剧本层。
- `data_bundle.rs` / `hot_reload.rs`：零 `include_str!` 纯磁盘 JSONC 读取器、跨表引用校验器与运行期原位无损热重载 / 重载重开局引擎。

### 2. 外部数据目录（`gamedata/`）
- `gamedata/catalog/`：`pop_types.jsonc`、`goods.jsonc`、`transport_hubs.jsonc` 及 `buildings/*.jsonc`（自动按文件名排序扫描加载）。
- `gamedata/rules/`：`ai_decision.jsonc`（AI 决策启发式参数）与 `events.jsonc`（声明式事件与脉冲规则）。
- `gamedata/maps/`：`earth_authored.json`（定稿地球维诺网格与大区数据）。
